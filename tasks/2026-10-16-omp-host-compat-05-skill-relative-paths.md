# Make skill file references resolve from the skill directory

## Routing and approvals

- tier: standard (S2 holds: one mechanical rewrite pattern; S8 weighed: about 40 references in 5 skills fit one session; S1, S3–S7 hold)
- accepted: by owner (2026-10-17, G-D1, owner decision in session decision message)

## Objective

Skill bodies point to their own files with repository-relative paths such as `.claude/skills/work/references/procedure.md`. Those paths exist only inside the G-Ingá checkout, or in a target repository that carries the pinned bundle. When OMP (or Claude Code) loads G-Ingá as a plugin in any other repository, the files sit in the plugin cache (for example `~/.omp/plugins/cache/plugins/g-inga___g-inga___0.0.0/…/work/`), and the agent is told to read paths that do not exist. Both hosts tell the model the skill's base directory when a skill is invoked: OMP appends `[Skill directory: <baseDir>]` and asks for relative paths to be resolved against it. Rewrite every such reference so it is relative to the skill directory.

In scope (paths after the canonical skills root layout):

- Every file under `skills/drive/`, `skills/orchestrate/`, `skills/sharpen/`, `skills/validator-flow/`, `skills/work/`, except `skills/work/references/artifact-contracts.md`, which is generated (see below).
- `manifest.json`, regenerated because the `work` and `sharpen` files are bundle assets.
- This task record.

Out of scope:

- `skills/work/references/artifact-contracts.md`. It is generated by `tools/validate/contract-copy.mjs`; if it holds such a path, change the generator input `docs/artifact-contracts.md` only when the path is a skill-file reference, then run `bun run build:contract-copy`.
- References to repository tools such as `tools/gate/verify-gate.ts`, `tools/validate/…` and `mise run …`. In repositories that are not G-Ingá these come from the pinned bundle; plugin-only repositories are not a supported target for `drive`/`orchestrate` (ADR 0005).
- Behavior changes of any kind; host dispatch wording (task 07).

## Acceptance criteria

- AC1: `grep -rnE '\.(claude|agents|opencode)/skills/|(^|[^./])skills/(drive|orchestrate|sharpen|validator-flow|work)/' skills/` prints nothing, except lines in `skills/work/references/artifact-contracts.md` that are not skill-file references (list them in `Note`).
- AC2: own-file references use the form `references/procedure.md` or `standard.md`, followed the first time in each file by `(relative to this skill's directory)`. Cross-skill references use the form `../work/references/model-policy.md`.
- AC3: worker dispatch prompts in `orchestrate` and `drive` no longer hand the worker a relative skill path. They say: "resolve `../work/references/procedure.md` against this skill's directory and give the worker the absolute path" (a subagent does not know the orchestrator's skill directory).
- AC4: plugin smoke outside the repository. Run the probe in Plan step 4 once: the answer is the first `#` heading of `skills/work/references/procedure.md`, read from the plugin cache.
- AC5: `bun run manifest` was run after the asset commit, `mise run validate` reports the bundle/manifest checks as `pass`, and `mise run validate` and `mise run test` pass.
