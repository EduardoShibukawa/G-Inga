## 1. Orchestrator + subagents + worktrees — VALIDATED

- Subagents "run in [their] own context window … and return only the summary"; purpose list includes "Preserve context by keeping exploration and implementation out of your main conversation" and "Control costs by routing tasks to faster, lower-cost models like Haiku". Source: <https://code.claude.com/docs/en/sub-agents>
- Subagent requests "count toward the same usage limits as your main conversation". So parallelism is not free under Pro quota. Source: <https://code.claude.com/docs/en/sub-agents>
- Prefer subagents over agent teams for "focused tasks where only the result matters" (lower token cost: "results summarized back to main context" vs "each teammate is a separate Claude instance"). Teams are "experimental and disabled by default" (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`), "use significantly more tokens", "token usage is roughly proportional to team size", start with 3–5 teammates, "two teammates editing the same file leads to overwrites — break the work so each teammate owns a different set of files". Our plan's choice of Task subagents (not agent teams) + disjoint scopes is exactly what docs recommend. Sources: <https://code.claude.com/docs/en/agent-teams>, <https://code.claude.com/docs/en/costs> ("approximately 7x more tokens … in plan mode")
- Community reference matches 1:1: tickets form "a task graph with blocking relationships … always a frontier of tickets which are ready to be grabbed"; "implementer subagents … each in its own worktree on its own branch"; "Communication to and from subagents should be sparse … primarily through context pointers"; implementers run "in the background where possible for maximum concurrency". Source: implement-spec SKILL (<https://raw.githubusercontent.com/mattpocock/skills/main/skills/engineering/implement-spec/SKILL.md>)
- Change if anything: (a) adopt native `isolation: worktree` frontmatter (subagent gets "an isolated copy of the repository … automatically cleaned up if the subagent makes no changes") instead of only hand-rolled `git worktree add` — <https://code.claude.com/docs/en/sub-agents>; (b) keep subagent `description` fields short — combined descriptions over 15,000 tokens trigger a startup warning — <https://code.claude.com/docs/en/sub-agents>; (c) never use agent teams here (no nested teams, no session resumption with in-process teammates — <https://code.claude.com/docs/en/agent-teams>).

## 2. Deterministic 5-layer gate — VALIDATED

- Hooks "execute automatically at specific points in Claude Code's lifecycle" with per-tool-call events `PreToolUse` / `PostToolUse` that "can block" the call; gate-relevant events exist: `SubagentStop`, `TaskCreated`, `TaskCompleted`, `TeammateIdle` ("runs when a teammate is about to go idle. Exit with code 2 to send feedback and keep the teammate working"), plus `PostToolUseFailure`, `Stop`, `PreCompact`. Source: <https://code.claude.com/docs/en/hooks>
- Enforcement pattern from docs: agent-teams page prescribes `TeammateIdle` / `TaskCreated` / `TaskCompleted` hooks with exit-2-to-block for quality gates. Source: <https://code.claude.com/docs/en/agent-teams>
- Community reference matches: two-axis review runs "both reviews in parallel sub-agents"; pin fixed point first (`git diff <fixed-point>...HEAD` three-dot, `git log <fixed-point>..HEAD`, `git rev-parse` check, fail on empty diff); Spec axis quotes spec lines, Standards axis cites standard file + rule; each report "Under 400 words"; "Do not merge or rerank findings". Our "review by a different model than the author" + ancestry check (`merge-base`) + word-bounded `ready_for_gate` return follows this shape. Source: code-review SKILL (<https://raw.githubusercontent.com/mattpocock/skills/main/skills/engineering/code-review/SKILL.md>)
- Change if anything: wire the gate as real hooks (`PostToolUse` on `Edit|Write` → lint/scope check; `SubagentStop`/`TaskCompleted` → L1–L5 judge with exit-2 block), not only manual `Bash` calls the main remembers to run; add `PreToolUse` deny rules for `rm *`/`push`/`deploy`/credential paths per docs pattern instead of relying on `permission.bash` text alone.

## 3. Antigravity manual air-gap — VALIDATED

- Verbatim FAQ (<https://antigravity.google/docs/faq/>): "Using third-party software, tools, or services to access Antigravity is a violation of our Terms of Service and severely degrades the experience for legitimate product users. Such actions can result in suspension or termination of your account. To use a third-party coding agent with Gemini, we recommend using a Gemini Enterprise or Google AI Studio API key."
- Verbatim FAQ (<https://antigravity.google/docs/faq/>): "Antigravity CLI headless mode (`agy -p`) is intended for direct scripting and CI workflows. Wrapping `agy` inside third-party coding agents or applications, or automating account rotation, is not supported under consumer plans."
- This covers the proposal §10.1 question explicitly: Opus 5.5 main running `agy -p` via its own `Bash` tool is both violations at once (third-party access + wrapping). The packet-print + human-paste path is the compliant shape. No change needed; keep "No OpenCode-to-`agy` bash tool, no `ginga --host agy` spawn, no account rotation."
- Corroborating quota facts: Pro = "high, generous quota, refreshed every five hours until the weekly limit is reached"; overage control is the **AI Credit Overages** setting (`Never`/`Always`); no BYOK for extra rate limits under consumer plans (<https://antigravity.google/docs/plans/>). Model table: Pro (non-trial only) gets Gemini 3.8 Flash + Claude Sonnet 5.5 / Opus 5.5 + Sonnet/Opus 4.6 + GPT-OSS-120b; Sonnet/Opus 4.6 and GPT-OSS-120b "will be removed on November 2, 2026"; quota bars are split (Gemini models vs Claude/GPT models) with Weekly + Five-Hour remaining (<https://antigravity.google/docs/models/>). Also: "Yes, you can use worktrees in the Antigravity app" (<https://antigravity.google/docs/faq/>) — validates running manual `agy` inside `../w-<id>`.
- Community match: the wizard pattern is "a bash script that walks a human, step by step, through a manual procedure … Don't invoke this for steps the agent can perform itself"; "Don't run it end-to-end yourself: it opens browsers and blocks on human input." Our handoff packet (agent authors exact command text + 2–4k token file, human pastes/runs) is this pattern applied to `agy`. Source: wizard SKILL (<https://raw.githubusercontent.com/mattpocock/skills/main/skills/engineering/wizard/SKILL.md>)
- Change if anything: track the two quota bars separately in `ginga budget` (never convert Pro 5h/weekly window to MTok — plan already states this, keep it); calendar-flag Nov 2 2026 model removals; default `AI Credit Overages: Never` (plan already does).

## 4. OpenCode elastic layer, own billing — VALIDATED

- Pro/Max OAuth in third-party tools removed in 1.3.0 and prohibited by Anthropic (quote in table above). Valid OpenCode auth: API keys via `/connect` (stored in `~/.local/share/opencode/auth.json`), Zen pay-per-request, Go subscription, OpenRouter, any OpenAI-compatible baseURL (Ollama/vLLM), `google` via `GEMINI_API_KEY`. Only OpenRouter `order`/`allow_fallbacks` and Go balance fallback give failover — no automatic cross-provider failover in core. Source: <https://opencode.ai/docs/providers/>
- Note asymmetry worth keeping in mind: OpenAI ChatGPT Plus/Pro OAuth and GitHub Copilot subscription login remain documented as supported in OpenCode (<https://opencode.ai/docs/providers/>) — the ban is Anthropic-specific, so "never with Claude Pro" is required while other vendor subscriptions are a vendor-policy question, not a blanket rule.
- Agent primitives match our needs: primary (`build` full-access, `plan` restricted) vs subagents (`general` full-access parallel units, `explore` read-only, `scout` dependency research); per-agent `model`, `permission` (allow/ask/deny incl. per-bash-pattern), `steps` (max agentic iterations, cost cap), `task` permission scoping which subagents an agent may spawn. Sources: <https://opencode.ai/docs/agents/>
- Change if anything: set `steps` caps on cheap OpenCode agents (implements the early-stop side of E3); use `permission.bash` glob patterns (`git *`, `grep *`) for the destructive/prod/creds policy; orchestrated Gemini goes through `google` provider + `GEMINI_API_KEY`, never consumer login (plan already states this).

## 5. Token economy thesis — VALIDATED

- "Delegate verbose operations to subagents so the verbose output stays in the subagent's context while only a summary returns"; "Agent teams use approximately 7x more tokens than standard sessions when teammates run in plan mode"; "A session that has been open for hours can use far more … usually … Long context: Claude Code sends your full conversation with every request … a one-line question in a session that has been open all day still draws usage for the whole conversation"; remedies: `/clear` between tasks, subagent model `haiku`, move detail out of CLAUDE.md (aim under 200 lines) into on-demand skills, hooks that grep logs instead of Claude reading 10k-line files, plan mode before implementation, stop/rewind early. Source: <https://code.claude.com/docs/en/costs>
- Prompt-cache lifetimes bound the resume math: 1h TTL on subscription, drops to 5 min when drawing on usage credits / API / cloud providers (<https://code.claude.com/docs/en/costs>) — supports the plan's "idle >60 min or context ≥80% → discard + Checkpoint resume" rule; do not assume a warm cache after a long break.
- Community match: slices are "tracer-bullet vertical slices … each sized to fit in a single fresh context window" with "blocking edges"; "avoid specific file paths or code snippets" in tickets (they go stale) — keep paths in the packet's In Scope, not in the ticket body. "Work the frontier: any ticket whose blockers are all done." Source: to-tickets SKILL (<https://raw.githubusercontent.com/mattpocock/skills/main/skills/engineering/to-tickets/SKILL.md>)
- Metric "cost per APPROVED task" is consistent with docs framing (per-developer $/active-day varies widely; pilot + measure with `/usage`, attribution breakdown, OTel export — <https://code.claude.com/docs/en/costs>). The plan's §9.3 calibration experiment (5 tasks × 3 routes A/B/C, first-try-pass ≥4/5 rule, throughput <1.6×/cost >1.4× stop rule) is the right way to replace H1–H3 hypotheses. No change needed.

## Bottom line

All 5 plan points are VALIDATED against owning primary sources; no contradictions found. Changes are additive (hook wiring, native worktree isolation, cache-TTL-aware budgeting, merger role, ticket-vs-packet path discipline) — none overturn the architecture. Highest-risk assumption remains correctly placed: any agent-spawned `agy` execution risks account suspension per verbatim FAQ, so the manual air-gap (point 3) is load-bearing, not optional.
