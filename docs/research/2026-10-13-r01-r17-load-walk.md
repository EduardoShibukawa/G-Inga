## 1. Method

This is a table-top walk. No agent session ran a scenario. Each cell is derived from the text of the bundle files, cited as `file Lnn` (line numbers at 36034be) or as a contract section (`§n`). Scenarios, expected tiers and deciding signals come from the EXP-01 frozen set [`docs/research/scenarios/r01-r17-v1.json`](scenarios/r01-r17-v1.json), which copies the [ADR 0002](../decisions/0002-ceremony-tiers-and-routing.md) §7 table. The earlier [table-top worksheet](2026-10-11-r01-r17-tabletop-worksheet.md) is the classification source; this note adds what it lacks: loading, reads and boundaries.

Three columns separate what enters the context from what the flow asks the agent to open:

- **Files loaded** is prompt loading. Before any invocation, every turn carries the pointer block and the `work` skill description. Invoking `/work` adds the `SKILL.md` body and nothing else: a skill's body loads on invocation, and supporting files load only when read (ADR 0005 §2, facts `N2` and `N4` in the [D5 evidence](d5-native-primitive-evidence.md)).
- **Files read** lists the bundle files the tier's text tells the agent to read, in order. "On demand" marks a file the text cites for a definition without an explicit "read" step. Repository files the work itself touches (the code under change, `git diff`, the task record) are named only when the flow prescribes them.
- **Tier boundary** names the rule that decides the tier and the rule that keeps the neighbouring tier out.

## 6. Limits

- A table-top walk shows what the text prescribes, not what a model does with it. Whether `/work` auto-loads for R01–R10 and R12–R17 is spike S1 (ADR 0005), which isn't part of this walk.
- Line numbers are valid for 36034be; the manifest hashes pin the same bytes.
- Compaction survival of `SKILL.md` (spec Verification item 4, spike S2) needs an interactive session. It's tracked in the task, not here.
